# План решения тестового задания AK Furs: AI-ассистент / администратор шоурума

## 1. Цель и контекст задачи
Создание полностью воспроизводимого, автоматизированного конвейера обработки данных без внешних зависимостей (на стандартной библиотеке Python), который очищает разнородные выгрузки (CRM, банк, прайс-лист со скрытым листом, чаты), формирует эталонный файл ответов `answers.json` по шаблону `answers_template.json` и готовит управленческие материалы (Q5).

## 3. Детальный план задач (Task Breakdown)

### Фаза 1. Архитектура скрипта и парсеры данных
- [ ] **1.1. Каркас `solve.py` на стандартной библиотеке Python**
  - Поддержка запуска: `python solve.py . > answers.json` или `python solve.py`
  - Отсутствие внешних зависимостей (`pandas`, `openpyxl`) для 100% воспроизводимости на любой машине.
- [ ] **1.2. Модуль чтения Excel без сторонних библиотек**
  - Распаковка `.xlsx` через `zipfile`.
  - Чтение `xl/sharedStrings.xml` и листов `xl/worksheets/sheet*.xml`.
  - Извлечение данных видимых листов (`Каталог`, `Переименования`, `Менеджеры`) и скрытого листа (`Прайс_история`).
  - Преобразование дат из серийного формата Excel (base: 1899-12-30) в объекты `datetime.date`.
- [ ] **1.3. Модуль парсинга банковской выписки**
  - Корректное декодирование кодировки `cp1251`.
  - Пропуск первой строки заголовка счёта.
  - Нормализация сумм (запятая на точку, удаление пробелов).
- [ ] **1.4. Модуль парсинга выгрузки CRM**
  - Универсальный парсер дат (серийные номера Excel, `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY`, русские названия месяцев «янв», «фев» и т.д.).
  - Парсер сумм и скидок (`2,48 млн` $\rightarrow 2\,480\,000$, `1,200.00` $\rightarrow 1200$, проценты).
  - Нормализация номеров заказов (удаление нецифровых символов, перевод в `int`).

### Фаза 2. Q1 — Очистка и дедупликация базы заказов
- [ ] **2.1. Нормализация статусов заказов**
  - Приведение к 4 статусам:
    - «Оплачен» (`Оплачен`, `PAID`, `оплачено` и вариации с пробелами);
    - «Отменён» (`Отменён`, `отменен`, `CANCELLED`);
    - «Возврат» (`Возврат`, `возврат`, `REFUND`);
    - «В работе» (все остальные: `NEW`, `Ждём оплату`, `в работе` и т.д.).
- [ ] **2.2. Разрешение дубликатов строк**
  - Составной ключ: `(order_id, line_no)`.
  - При наличии нескольких записей выбирается строка с максимальным значением даты/времени `Выгружено`.
- [ ] **2.3. Расчёт метрик Q1**
  - `q1_unique_orders`: количество уникальных `order_id` после дедупликации.
  - `q1_unique_order_lines`: общее количество уникальных строк заказов после дедупликации.

### Фаза 3. Q2 — Банковская сверка
- [ ] **3.1. Идентификация заказов в выписке**
  - Фильтрация операций: только `Тип == "Поступление"`.
  - Извлечение кандидатов на номер заказа из `Назначения платежа` регулярными выражениями (`заказ N`, `зак. N`, `счёт № N`, `A-00N`, `A N` и т.д.).
  - Исключение ложных срабатываний: даты (`от 16.02.2026`), телефоны (`+7 ...`), суммы.
  - Проверка принадлежности извлечённого номера к множеству существующих заказов из CRM.
- [ ] **3.2. Расчёт метрик Q2**
  - `q2a_paid_orders_without_payment`: список номеров заказов со статусом «Оплачен», по которым нет ни одного поступления в выписке (сортировка по возрастанию).
  - `q2b_unidentified_payments_count`: количество поступлений, не привязанных ни к одному существующему заказу.
  - `q2b_unidentified_payments_sum_rub`: общая сумма неопознанных поступлений в рублях.

### Фаза 4. Q3 — Контроль соблюдения минимальных цен
- [ ] **4.1. Построение дерева актуальных артикулов и истории цен**
  - Сопоставление старых и новых артикулов из листа `Переименования` с датой перехода.
  - Маппинг артикула из CRM на канонический артикул в `Прайс_история`.
  - Поиск интервала дат `[Действует с, Действует по]`, включающего дату создания заказа.
- [ ] **4.2. Расчёт фактической цены за единицу с учётом скидки**
  - Если скидка в `%`: $\text{Цена со скидкой} = \text{Цена} \times (1 - \text{Скидка} / 100)$.
  - Если скидка числом (рубли): $\text{Цена со скидкой} = \text{Цена} - (\text{Скидка} / \text{Кол-во})$.
- [ ] **4.3. Выявление нарушений и группировка**
  - Исключение заказов со статусом «Отменён».
  - Условие нарушения: $\text{Цена со скидкой} < \text{Минимально допустимая цена} - 10^{-4}$.
  - Маппинг менеджера из CRM на каноническое имя из листа `Менеджеры`.
  - `q3_price_violation_lines_total`: общее число строк с нарушениями.
  - `q3_price_violation_lines_by_manager`: словарь с количеством нарушений по каждому каноническому менеджеру.

### Фаза 5. Q4 — Аудит переписок с клиентами
- [ ] **5.1. Парсинг файлов диалогов (150 файлов)**
  - Извлечение ID чата, автора и текста каждой реплики с сохранением порядка.
- [ ] **5.2. Детекция событий**
  - Детекция озвучивания цены **менеджером** (числа с `₽`, `руб`, слова «тысяч», текстовые числительные; игнорирование реплик клиента).
  - Детекция приглашения на встречу/примерку **менеджером** («приезжайте», «приглашаю на примерку», «когда вам удобно», «ждем вас в ателье» и аналоги).
- [ ] **5.3. Анализ хронологии и валидация**
  - Фиксация случаев, где индекс/время первого приглашения строго меньше первого озвучивания цены.
  - Ручная верификация спорных и граничных случаев (например, C0010).
  - `q4_chats_meeting_before_price`: отсортированный список ID чатов.
