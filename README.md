# AK Furs — обработка данных тестового задания

Скрипт `src/solve.py` выполняет этапы Q1–Q5 тестового задания: очищает выгрузку CRM, сверяет поступления из банковской выписки, проверяет цены по истории прайса, анализирует переписки и формирует итоговые материалы.

## Требования

- Python 3.10 или новее.
- Внешние Python-пакеты не требуются: скрипт использует стандартную библиотеку.

## Входные данные

По умолчанию скрипт ищет файлы в `Initial project data/` относительно корня проекта.

| Файл или каталог | Формат | Использование и особенности |
| --- | --- | --- |
| `01_crm_orders_export.csv` | CSV, UTF-8, разделитель `;` | Заказы и их строки: даты, менеджеры, артикулы, количество, цены, скидки и статусы. |
| `02_bank_statement_rub.csv` | CSV, CP1251, разделитель `;` | Банковские операции. В сверке учитываются поступления. |
| `03_catalog_prices_reference.xlsx` | Excel XLSX | Каталог, переименования артикулов, менеджеры и история цен. История цен может находиться на скрытом листе. |
| `answers_template.json` | JSON, UTF-8 | Шаблон и порядок полей итогового `answers.json`. |
| `chats/` | 150 текстовых файлов UTF-8 | Переписки `C0001.txt`–`C0150.txt`, используемые для Q4 и ответа клиентке по C0010. |

Скрипт читает исходные файлы, но не изменяет их. Все результаты сохраняются отдельно в `output/`.

## Запуск

Из корня проекта в Windows PowerShell:

```powershell
python src\solve.py
```

Результаты будут записаны в `output\`. Итоговый JSON также печатается в стандартный вывод, поэтому его можно перенаправить:

```powershell
python src\solve.py > answers.json
```

Сообщения о созданных файлах и ошибки выводятся в стандартный поток ошибок, а не смешиваются с JSON.

### Передача других входных файлов

Можно указать каталог с данными целиком:

```powershell
python src\solve.py "D:\AK Furs\data" --output "D:\AK Furs\results"
```

Либо переопределить отдельные пути:

```powershell
python src\solve.py `
  --crm "D:\AK Furs\data\crm.csv" `
  --bank "D:\AK Furs\data\bank.csv" `
  --catalog "D:\AK Furs\data\catalog.xlsx" `
  --template "D:\AK Furs\data\answers_template.json" `
  --chats "D:\AK Furs\data\chats" `
  --output "D:\AK Furs\results"
```

Аргумент `data_dir` задаёт каталог по умолчанию для входных файлов. Параметры `--crm`, `--bank`, `--catalog`, `--template` и `--chats` позволяют переопределить соответствующие пути независимо. Для просмотра всех параметров:

```powershell
python src\solve.py --help
```

## Что делает скрипт

1. **Q1 — очистка CRM.** Нормализует номера заказов и статусы, удаляет повторные строки по паре «заказ + строка», оставляя наиболее позднюю выгрузку.
2. **Q2 — сверка платежей.** Находит номера заказов в назначениях поступлений и сопоставляет их с CRM. В том числе учитываются номера после формулировок «счёт», «счёта», «счёту» и «счётом», если номер существует в CRM. Если найдено несколько заказов-кандидатов, платёж автоматически не связывается.
3. **Q3 — проверка цен.** Сопоставляет артикулы с каталогом и историей переименований, выбирает минимальную цену, действовавшую на дату заказа, и учитывает скидку и количество.
4. **Q4 — анализ переписок.** Находит у менеджера реплики с приглашением на встречу или примерку и реплики с озвучиванием цены, затем проверяет их временной порядок. Если первые события имеют одинаковую временную метку, чат считается неоднозначным и не попадает в список подтверждённых нарушений.
5. **Q5 — итоговые материалы.** Формирует JSON по шаблону, записку руководителю и текст ответа клиентке в чате C0010.

## Результаты

После успешного запуска в `output/` создаются или обновляются:

| Файл | Содержимое |
| --- | --- |
| `answers.json` | Ответы Q1–Q4 и примечания в структуре `answers_template.json`. |
| `management_memo.md` | Краткая записка руководителю с тремя бизнес-рисками и рекомендациями. |
| `client_message_C0010.txt` | Предлагаемый ответ клиентке из переписки C0010. |
| `bank_payment_audit.csv` | Назначения, кандидаты на номер заказа и результат разбора платежей для ручной проверки. |
| `q4_chat_audit.csv` | Найденные события и подтверждающий текст, временные метки, номера строк и неоднозначности по чатам. |
| `ai_validation_notes.md` | Краткое описание проверок и принятых правил обработки. |

В записке расчётное отклонение от минимальных цен обозначено как оценка расхождения, а не доказанный убыток. Аудит-файлы сохраняют основания для ручной проверки неоднозначных случаев.

## Проверка

Запуск регрессионных тестов из корня проекта:

```powershell
python -m unittest discover -s tests -v
```

Тесты покрывают, в частности, нормализацию заказов и менеджеров, разбор неоднозначных платежей, расчёт скидок, выбор исторической цены, хронологию событий чата и обработку одинаковых временных меток.

## Особенности и ограничения

- Для Excel используется чтение формата XLSX средствами стандартной библиотеки; внешние библиотеки для таблиц не нужны.
- Требуемые листы книги, в том числе скрытые, читаются из структуры XLSX.
- Неверные или отсутствующие обязательные числовые значения приводят к ошибке, а не подменяются нулём.
- Выявление событий в переписке основано на правилах и текстовых эвристиках. Аудит содержит исходные реплики, чтобы спорные результаты можно было проверить вручную.
- Скрипт ожидает 150 файлов чатов формата `C*.txt`. Если набор неполный, обработка завершается ошибкой.
- `answers.json` должен соответствовать ключам и их порядку из переданного `answers_template.json`; несовместимый шаблон приводит к ошибке.
